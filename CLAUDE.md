# Echips Driver Assistant — задание для Claude Code

## Работа с git (проект синхронизируется между несколькими устройствами)

Перед началом любой работы — **обязательно** `git pull`, чтобы не затереть
изменения, сделанные на другом компьютере. После завершения работы —
закоммить и запушить (`git add -A && git commit -m "..." && git push`),
даже если пользователь явно не попросил — иначе на другом устройстве
не будет видно сделанного здесь.

## Контекст проекта

Это Windows-приложение на Tauri (Rust + HTML/CSS/JS), которое:
1. Определяет модель ноутбука через WMI/PowerShell (имя модели → префикс
   серийного номера → ручной выбор пользователем).
2. Ищет модель в каталоге `manifest.json`, размещённом на Yandex Disk.
3. Скачивает нужный пакет драйверов по публичной ссылке Yandex Disk
   (без токенов, через их публичный API).
4. Устанавливает драйверы через `pnputil /add-driver *.inf /subdirs /install`.
5. Если модель не определена — запасной режим: устанавливает только
   недостающие категории драйверов (Wi-Fi, звук, Bluetooth и т.д.) из
   общей папки "Universal".

Все требования к правам администратора, каскад определения модели, и
дизайн интерфейса уже согласованы и реализованы — весь код прислан
готовым, твоя задача **не переписывать логику**, а довести проект до
рабочего собранного `.exe` и помочь с доводкой на месте.

## Структура проекта

```
echips-driver-assistant/
  src/                     <- фронтенд (HTML/CSS/JS), логика в app.js

  manifest/manifest.json        <- каталог моделей (сейчас с плейсхолдерами ссылок)
  README.md                       <- подробная инструкция по сборке
```

## Что нужно сделать в первую очередь

1. **Проверить и поправить компиляцию.** Код написан без доступа к
   реальному Windows + MSVC + WebView2 окружению — то есть весьма
   вероятны мелкие несостыковки версий API Tauri 2.x, названий полей
   и т.п. Запусти `cargo tauri dev`, разбери ошибки компиляции по
   порядку, поправь.
2. **Сгенерировать иконки** — `cargo tauri icon путь/к/логотипу.png`
   (лого лежит в `src/logo.png`, но для иконки лучше взять оригинал
   в максимальном разрешении, если он есть отдельно).
3. **Проверить работу вживую**: `cargo tauri dev`, посмотреть все
   экраны, особенно:
   - действительно ли WMI-команды возвращают данные в нужном формате
     (PowerShell → JSON → десериализация в Rust)
   - работает ли обращение к Yandex Disk API (сейчас в `manifest.json`
     стоят placeholder-ссылки — для реального теста нужно будет либо
     подставить настоящие, либо временно замокать эти вызовы)
   - корректно ли обновляется прогресс-бар через события Tauri
     (`window.emit` в Rust → `listen` в JS)
4. Когда всё стабильно работает — собрать финальный .exe с красивым
   именем через `build_release.ps1` в корне проекта (запускает
   `cargo tauri build --no-bundle` и сразу переименовывает результат в
   "Echips Driver Assistant.exe" — обычный `cargo tauri build` даст файл
   `echips-driver-assistant.exe`, это не баг, а ограничение самого Cargo
   на пробелы в имени бинарника).

## Не трогать без обсуждения с пользователем

- Формат `manifest.json` (ключи `yandex_public_key`, `path`, `diagonal`,
  `_universal`) — под него уже подстроена вся логика сопоставления,
  менять формат — значит менять и Rust, и JS одновременно.
- Список категорий `categoryMap` в `app.js` / `class_to_category` в
  `main.rs` — соответствие PNPClass → название файла категории.
  Расширять можно, менять существующие значения — только если
  пользователь подтвердит, что реальные файлы в Yandex Disk называются
  иначе.

## ЗАКРЕПЛЁННЫЕ ИСПРАВЛЕНИЯ — НЕ ОТКАТЫВАТЬ

**Иконки (`src-tauri/icons/`) периодически оказываются пустыми — это не баг
очистки, а то, что они никогда не были закоммичены в git.** Папка `icons/`
изначально создавалась как пустая заготовка — реальные файлы (`icon.ico`,
`32x32.png`, `128x128.png`, `128x128@2x.png`) генерируются локально командой
`cargo tauri icon путь/к/logo.png` (см. раздел ниже в README). Если эти
сгенерированные файлы не закоммичены в git, любой свежий клон/checkout
получит пустую папку заново, и сборка упадёт на `icon.ico not found`.
**Решение:** после генерации — обязательно `git add -f src-tauri/icons/` и
закоммитить, проверив заодно `.gitignore` на предмет случайных широких
паттернов, которые могли бы это исключить.

Эти три фикса уже применены и проверены. Если при последующей работе видишь,
что что-то из этого списка отсутствует в коде — это регресс, а не "старая
версия, которую можно проигнорировать". Восстанови как описано ниже.

1. **Нет консольного окна при запуске и при системных вызовах.**
   `main.rs` начинается с `#![cfg_attr(not(debug_assertions),
   windows_subsystem = "windows")]`, импортирует `CommandExt` и объявляет
   `const CREATE_NO_WINDOW: u32 = 0x08000000;`. Каждый `Command::new(...)`
   для `powershell`/`shutdown` собирается через `let mut cmd = ...;
   cmd.args([...]); #[cfg(target_os = "windows")] cmd.creation_flags(
   CREATE_NO_WINDOW);` — НЕ через однострочный `Command::new(...).args(...)
   .output()`.

2. **Манифест администратора — через `tauri_build`, не через `winres`.**
   `build.rs` использует `tauri_build::WindowsAttributes::new()
   .app_manifest(...)` + `tauri_build::try_build(attributes)`, а НЕ
   `winres::WindowsResource::new().compile()` — последний создаёт
   конфликтующий Windows-ресурс VERSION и ломает линковку
   (`CVT1100: duplicate resource`). Манифест обязательно включает и
   `requireAdministrator`, и `<dependency>` на
   `Microsoft.Windows.Common-Controls` версии 6.0.0.0 — без второго
   WebView2 падает при старте с ошибкой `TaskDialogIndirect не найдена`.
   `winres` полностью убран из `[build-dependencies]` в `Cargo.toml`.

3. **Никакого NSIS-инсталлятора — только голый `.exe`.**
   `tauri.conf.json` → `"bundle"` → `"active": false`. Соответственно,
   `.github/workflows/build.yml` собирает через `cargo tauri build
   --no-bundle` и публикует артефакт из
   `src-tauri/target/release/echips-driver-assistant.exe`, а не из
   `bundle/nsis/`. Если понадобится вернуть инсталлятор — это
   осознанное решение, а не автоматический откат: сначала спросить
   пользователя.

4. **Готовый .exe должен называться "Echips Driver Assistant.exe" с пробелами.**
   Cargo/Rust не разрешает пробелы в имени самого бинарника, поэтому
   в `.github/workflows/build.yml` есть отдельный шаг "Переименование
   в красивое имя файла" — простое копирование собранного
   `echips-driver-assistant.exe` в файл с пробелами в названии перед
   публикацией артефакта. Это не лишний/дублирующий шаг — не убирайте
   его при рефакторинге workflow.

5. **exe не должен зависеть от VC++ Redistributable на целевой машине.**
   `src-tauri/.cargo/config.toml` задаёт
   `rustflags = ["-C", "target-feature=+crt-static"]` для таргета
   `x86_64-pc-windows-msvc` — статически линкует рантайм MSVC прямо в
   exe. Без этого файла программа падает на чистой Windows с ошибкой
   "не обнаружена VCRUNTIME140_1.dll", потому что по умолчанию Rust
   линкуется с системными vcruntime-библиотеками, которых нет на
   компьютере без установленной Visual Studio/VC++ Redistributable.
   Если при сборке с этим флагом возникнут ошибки линковки у каких-то
   зависимостей (redistributable-конфликт) — разбираться с конкретной
   зависимостью, а не удалять флаг целиком, иначе баг с VCRUNTIME
   вернётся.

6. **Кастомная шапка окна (после отключения decorations) требует явных
   разрешений Tauri 2 на управление окном.**
   `src-tauri/capabilities/default.json` должен включать
   `core:window:allow-minimize` и `core:window:allow-close` в списке
   `permissions` — набор `core:default` НЕ включает эти команды сам по
   себе. Без них вызовы `getCurrentWindow().minimize()` /
   `.close()` из JS тихо отклоняются бэкендом (ошибка уходит в консоль
   WebView, не в UI) — кнопки в кастомной шапке выглядят нажатыми, но
   ничего не происходит. Если разрешения "почистят" обратно до
   `core:default` при рефакторинге — кнопки свернуть/закрыть снова
   перестанут работать без видимой причины.

## Второй этап доработки (уже реализован, проверить при сборке)

В `main.rs` добавлены новые команды и зависимости — если возникнут ошибки
компиляции, скорее всего дело в версиях крейтов, а не в логике:
- `tauri-plugin-notification` — системные уведомления по завершении установки.
- `create_restore_point` — вызывает `Checkpoint-Computer` через PowerShell.
- `cache_manifest` / `load_cached_manifest` — кэш каталога в
  `%LOCALAPPDATA%\Echips\manifest_cache.json`.
- `open_log_folder` — открывает `%LOCALAPPDATA%\Echips\logs\` в проводнике.
- `fetch_public_json` — переименована из `fetch_manifest`, теперь
  используется и для manifest.json, и для version.json (проверки обновлений).
- `download_and_install` теперь принимает доп. параметр `create_restore:
  bool` и возвращает структуру `InstallResult` (message, installed_drivers,
  log_path), а не просто строку — если правите эту функцию, не сломайте
  сигнатуру, `app.js` ожидает именно такой ответ.

При первом `cargo tauri dev` внимательно проверьте, что `tauri-plugin-
notification` версии 2.x совместим с остальными зависимиями — это
относительно новый плагин, версии могли разойтись.

Полная инструкция по установке инструментов (Rust, Node, Tauri CLI,
MSVC Build Tools) и пошаговый план сборки — в `README.md` в корне
проекта. Прочитай его первым делом.
