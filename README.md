# Echips Driver Assistant — Tauri-версия

Полный перенос логики из Python-прототипа (`driver_assistant_client.py`) на
Tauri: Rust-бэкенд для системных вызовов и работы с Yandex Disk, HTML/CSS/JS
для интерфейса на основе согласованного дизайн-прототипа.

## Структура проекта

```
echips-driver-assistant/
  src/                    <- фронтенд (HTML/CSS/JS)
    index.html
    style.css
    app.js
    logo.png              <- ваш логотип (уже вставлен)
  src-tauri/               <- Rust-бэкенд
    Cargo.toml
    build.rs                <- встраивает манифест "requireAdministrator"
    tauri.conf.json
    src/main.rs              <- вся логика: WMI, Yandex Disk, pnputil
    icons/                     <- СЮДА нужно положить иконки (см. ниже)
  manifest/
    manifest.json               <- каталог моделей с реальными данными
```

## Что уже сделано и проверено

- Вся логика каскада (имя модели → префикс серийника → ручной выбор →
  универсальный набор) перенесена на Rust и покрыта тестами на ваших
  реальных данных (BM156UL-RH, XPS15, диагонали с двумя мониторами) —
  все тесты проходят.
- Дизайн интерфейса перенесён из согласованного HTML-прототипа:
  тот же шестиугольный индикатор, шрифты, цвета, логотип, футер со
  ссылкой на echips.ru.
- `manifest.json` заполнен пятью моделями из присланных вами данных.

## Что нужно доделать вам (или через Claude Code)

Собрать и протестировать реальный `.exe` я не могу — для этого нужны
Windows, компилятор Rust с MSVC-таргетом и системный WebView2, которых
нет в моей текущей среде. Дальнейшие шаги — на вашей машине:

### 1. Установить инструменты (один раз)

- [Rust](https://rustup.rs/) — `rustup-init.exe`, стандартная установка
- [Node.js](https://nodejs.org/) — LTS-версия
- Tauri CLI: `cargo install tauri-cli --version "^2.0.0"`
- Microsoft C++ Build Tools (нужны для компиляции под Windows) —
  ставится вместе с Visual Studio Installer, компонент "Desktop
  development with C++"

### 2. Подставить реальные ссылки

- В `src/app.js` — константа `MANIFEST_PUBLIC_URL` в самом начале файла.
- В `manifest/manifest.json` — все `yandex_public_key` (сейчас плейсхолдеры).
  Сам файл нужно залить на Yandex Disk отдельно и получить публичную ссылку
  на НЕГО САМОГО — именно эта ссылка идёт в `MANIFEST_PUBLIC_URL`.
- Проверить/поправить диагонали моделей, отмеченные как предположение
  по неймингу (см. комментарии в переписке) — особенно если реальная
  диагональ окажется другой.

### 3. Иконки приложения

Tauri требует набор иконок разных размеров в `src-tauri/icons/`. Проще
всего сгенерировать их автоматически из одного PNG командой:

```
cargo tauri icon путь/к/вашему/логотипу.png
```

Она сама создаст все нужные размеры и `.ico` для Windows.

### 4. Запуск в режиме разработки (для проверки на своей машине)

```
cd echips-driver-assistant
npm install    # если будете использовать npm-скрипты; можно и без него
cargo tauri dev
```

Откроется окно приложения — на нём сразу видно, работает ли определение
модели, подключение к Yandex Disk и т.д. Через Claude Code это делать
особенно удобно: он сам увидит ошибки компиляции в терминале и поможет
их поправить на месте, не пересылая скриншоты, как мы делали с
Inno Setup.

### 5. Сборка финального .exe

```
cargo tauri build
```

Готовый инсталлятор (NSIS) появится в
`src-tauri/target/release/bundle/nsis/`.

## Автоматическое создание архивов под модели

Вместо того чтобы вручную создавать пустой zip под каждую новую модель,
запускайте `tools/generate_model_archives.py`:

```
cd tools
python generate_model_archives.py --only-missing
```

Скрипт читает `manifest/manifest.json` и создаёт по пустому архиву
(`<Модель>_drivers.zip`) для каждой модели — просто перетаскиваете туда
файлы драйверов и заливаете на Yandex Disk, как обычно. Флаг
`--only-missing` пропускает модели, у которых уже стоит настоящая ссылка
(не плейсхолдер) — удобно при повторных запусках, когда часть моделей уже
заполнена. Без флага скрипт создаст архивы под все модели сразу (но не
тронет уже существующие файлы в папке вывода).

## Новые функции (второй этап доработки)

### 1. Точка восстановления системы
На экране подтверждения есть чекбокс "Создать точку восстановления перед
установкой" (включён по умолчанию). Если пользователь согласен, перед
загрузкой драйверов вызывается `Checkpoint-Computer`. **Важно:** Windows по
умолчанию не даёт создавать точки восстановления чаще одного раза в 24
часа — это ограничение самой системы, не баг программы; при повторном
запуске программы в тот же день точка может не создаться, об этом будет
сказано в логе.

### 2. Полный лог установки
Каждая установка пишет подробный лог в
`%LOCALAPPDATA%\Echips\logs\install_<timestamp>.log` — включая обнаруженное
оборудование, выбранные файлы, полный вывод `pnputil`. На экране результата
есть кнопка "Открыть папку с логом" — сразу открывает эту папку в проводнике.

### 3. Кэш последнего успешного manifest.json
При успешной загрузке каталог сохраняется в
`%LOCALAPPDATA%\Echips\manifest_cache.json`. Если при следующем запуске
интернета нет или Yandex Disk недоступен — программа автоматически
использует последнюю сохранённую копию вместо немедленной ошибки.

### 4. Проверка свободного места
Перед началом загрузки Rust-бэкенд проверяет свободное место на диске,
где расположена системная временная папка. Порог — `MIN_FREE_MB = 500`
(в `main.rs`) — при необходимости увеличьте под размер реальных пакетов
драйверов.

### 5. Проверка обновлений и скачивание новой версии
Настройте `VERSION_CHECK_URL` в `src/app.js` — ссылку на публичный
`version.json` на Yandex Disk (пример лежит в `manifest/version.json`).
Текущая версия приложения — константа `APP_VERSION` в том же файле,
повышайте её при каждом релизе.

Формат `version.json`:
```json
{
  "latest_version": "3.5.0",
  "yandex_public_key": "https://disk.360.yandex.ru/d/ссылка_на_новый_exe",
  "file_name": "EchipsDriverAssistant.exe",
  "download_url": "https://echips.ru/download"
}
```

Если версия на сервере новее — сверху показывается баннер с кнопкой
"Скачать". Логика такая:
- Если в `version.json` заполнен `yandex_public_key` — приложение **само**
  скачивает новый `.exe` прямо с того же Yandex Disk (тем же способом,
  что и драйверы) в папку "Загрузки", показывает прогресс в баннере, а
  по завершении открывает проводник с уже выделенным файлом — пользователю
  остаётся только запустить его вручную. **Это временное решение**, пока
  нет отдельной страницы загрузки на сайте.
- Если `yandex_public_key` не указан (или не заполнен) — работает старое
  поведение: клик по "Скачать" просто открывает `download_url` в браузере.

Само приложение не может подменить свой же запущенный `.exe` — это
системное ограничение Windows, поэтому финальный запуск нового файла
всё равно делает сам пользователь. Полноценный самообновляющийся
установщик (с автоматическим перезапуском) — на будущее.

### Дизайн-доработки
- Иконки категорий в универсальном наборе (Wi-Fi, звук, Bluetooth и т.д.).
- Поиск по списку моделей (актуально при большом каталоге — 80+ записей).
- Системное уведомление Windows по завершении установки.
- Чек-лист файлов с живыми отметками "✓" при установке нескольких категорий.
- Разворачиваемый список установленных пакетов драйверов на экране успеха.

## Важные технические заметки

- **Права администратора** встраиваются через `build.rs` (манифест
  `requireAdministrator`) — Windows сама покажет UAC при запуске,
  вручную включать не нужно, как и в Inno Setup-версии.
- **pnputil** вызывается один раз после распаковки всех скачанных
  архивов — так же, как в Python-версии.
- **Категории универсального набора** сопоставляются в `app.js` напрямую
  по классу устройства Windows (`Net`, `Media`, `Bluetooth`, `System` и
  т.д.) — файлы в папке Universal на Yandex Disk должны называться так же.
- Слушатель `install-progress` в `app.js` получает события напрямую из
  Rust (`window.emit(...)` в `main.rs`) — прогресс-бар обновляется в
  реальном времени, без опроса.
